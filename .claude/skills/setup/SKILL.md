# Настройка с нуля

Движок — публичный репозиторий: навыки, скрипты, документация, ни одного документа и ни одного
реквизита. Данные — отдельный приватный репозиторий: `profile.json`, папки месяцев, финансы,
договоры, образцы подписи. Задача этого навыка — довести человека от свежего клона движка
до состояния «доктор зелёный, можно закрывать месяц».

Подробный текст для чтения глазами — `docs/setup.md`; здесь порядок работы с владельцем.
Развёрнутое описание ролей интеграций — `docs/integrations.md`.

| Команда | Что делаю |
|---|---|
| «Настрой окружение» | пройти шаги ниже по порядку, спрашивая только то, что нельзя узнать |
| «Проверь окружение» | только `scripts/doctor.py` и разбор того, что он показал |

## Правила разговора

- **Спрашивать по одному блоку, а не всё сразу.** Владелец не помнит наизусть ИБАН
  и шифру делатности — дай ему найти документ.
- **Показывать, откуда брать значение.** Каждое поле конфига имеет источник: решение
  налоговой, карточка счёта, договор с клиентом. Если источник неизвестен — так и сказать,
  а не выдумывать формат.
- **Ничего не отправлять и не коммитить.** Настройка целиком локальная.
- **Не заполнять реквизиты угадыванием.** Пустое поле лучше выдуманного: скрипты падают
  с понятным сообщением на пустом и молча делают неверный документ на выдуманном.

## Шаги

1. **Инструменты и окружение.**

   ```bash
   python3 scripts/doctor.py
   ```

   Он же и чек-лист: покажет, каких бинарников нет и каким пакетом ставятся. Ставит их
   владелец сам — системные пакеты навык не устанавливает. Окружение разработки (линтер
   и тесты) нужно только тому, кто будет править движок:

   ```bash
   python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
   ```

   Если `venv` падает на отсутствии `ensurepip` (в Debian и Ubuntu это отдельный пакет
   `python3-venv`), выручает `virtualenv .venv` — он приносит `pip` с собой.

2. **Приватный репозиторий данных.** Спросить, где он должен лежать (по умолчанию — рядом
   с движком), и создать скелет:

   ```bash
   scripts/init_private.sh <каталог данных>
   ```

   Что появится: каталоги месяцев и финансов, `profile.json` из образца, симлинк `engine`
   на движок, симлинк `.claude/skills`, тонкий `CLAUDE.md`, `.gitignore`, пре-коммит
   и репозиторий git. Скрипт идемпотентен и существующий репозиторий не трогает.

   Дальше **работа идёт из каталога данных**: скрипты движка вызываются как
   `python3 engine/scripts/<имя>.py`, корень данных они находят сами.

3. **`profile.json` по блокам.** Заполнять вместе с владельцем, объясняя источник:

   | Блок | Что спросить | Откуда владелец это берёт |
   |---|---|---|
   | `entrepreneur` | имя, название фирмы, ПИБ, шифра делатности, адрес, место издавања, телефон, ящик | решение о регистрации и решение налоговой; `izjava_name` — как имя написано в банковских бланках |
   | `accounts` | динарский счёт, девизный счёт, его IBAN, цифры личного счёта | карточка счёта из банка; IBAN — тот, который клиент указывает в платеже |
   | `mail` | ящик, папка писем банка, папка выписок, отправитель счетов поставщиков | из почтового клиента; папки — **брать из результата поиска**, а не собирать руками |
   | `integrations` | чем закрыты роли `tasks`, `chat`, `mail`, `accounting` | `docs/integrations.md`; по умолчанию — то, что стоит у автора |
   | `client` | название, адрес, налоговый номер, канал и учётка в мессенджере, `chat_languages` и `act_languages` | договор с клиентом и его карточка; языки — на каких он читает список работ и на каких выписан акт |
   | `suppliers` | по каждому: имя, прежнее имя, жиро-счёт, предмет | счета, которые он присылает |
   | `gpg` | получатель для контейнера образцов | `gpg --list-keys`; ключ должен быть свой |
   | `limits` | годовой лимит паушала | актуальный порог в законе |

   Заглушки из образца доктор показывает отдельной строкой — пройтись по ним и заменить.

4. **Интеграции.** По `docs/integrations.md` подключить то, чем закрыты роли, и проверить
   в сессии (`/mcp`). Если владелец пользуется другим трекером или мессенджером — сказать
   прямо: роль заменяется, но раздел «Адаптер» в навыках придётся переписать под новые
   вызовы, и это работа на один раз.

5. **Библиотека образцов подписи** — навык `signatures`, команда «Собери библиотеку
   подписей». Без неё работает всё, кроме подписания документов.

6. **Проверка на синтетике.** Показать, что цепочка живая, не дожидаясь первых настоящих
   документов:

   ```bash
   python3 engine/scripts/make_examples.py tmp/example-data
   TASKS_DATA=tmp/example-data python3 engine/scripts/build_report.py
   TASKS_DATA=tmp/example-data python3 engine/scripts/kpo_book.py --offline
   ```

   Что здесь не проверяется: разбор выписок банка (нужны настоящие PDF своего банка)
   и выгрузка в бухгалтерский сервис (сверяется по трём документам).

7. **Итог.** Прогнать `doctor.py` ещё раз и показать, что осталось незакрытым, с ссылкой
   на документ по каждому пункту. Затем назвать первые рабочие команды: «Собери задачи»
   (навык `monthly-tasks`) и «Обнови финансы» (навык `finance`).

## Что не входит в настройку

- **Установка системных пакетов** — только руками владельца.
- **Правка навыков под другой трекер или мессенджер** — отдельная работа по
  `docs/integrations.md`, не часть настройки.
- **Первый коммит в оба репозитория** — по команде владельца, не по своей инициативе.
