# Как устроено подписание

Читать, когда скрипт упал или его надо править. Порядок действий при поломке — в `SKILL.md`,
раздел «Если документ изменился». Что менялось в формах исторически — в `docs/history.md`.

## Геометрия подписи

Правила одинаковы для всех трёх типов документов, живут в `scripts/sign_pdf.py`
(`norm_scale`, `baseline_row`) и переиспользуются остальными скриптами. Каждое из них —
следствие конкретной ошибки, которую видно глазами; менять, не разобравшись, не стоит.

- **По горизонтали — по центру поля.** Не от начала линии: подпись, прижатая влево, выглядит
  приклеенной к краю. В `Izjava` исключение — там на линии ещё печатается имя, подпись идёт
  сразу справа от него.
- **По вертикали — базовая линия письма чуть ниже линии документа**, чтобы штрихи её **заметно
  пересекали**. Не «стоять на линии, касаясь» и не «висеть ниже» — оба варианта выглядят
  неправдоподобно.
- **Привязка к базовой линии образца, а не к нижнему пикселю.** У части образцов есть нижний
  вынос; по крайнему пикселю такие подписи вставали бы выше остальных. `baseline_row` находит
  строку, где стоит основная масса штрихов (нижняя строка с плотностью чернил ≥20% от максимума).
- **Линия ищется в растре, а не по `pdftotext -bbox`.** Рамка слова-подчёркивания ниже
  нарисованной линии на глубину выносного элемента шрифта (3–4 pt), и промах на эти пункты
  визуально заметен. `pdfobj.hline_in_box` находит саму линию по растру 150 dpi.
- **Масштаб нормируется по площади чернил** к эталону 84 pt по ширине при пропорции 0.203
  (медиана набора образцов). По одной ширине нормировать нельзя: пропорции образцов разнятся
  на ±25%, и «плоские» подписи выглядели заметно мельче. Ширина дополнительно ограничена
  длиной линии.
- **Один и тот же эталон размера** применяется и к акту, и к бланкам банка — подпись
  в разных документах должна выглядеть одного размера.
- Разметка образцов — `signatures/METRICS.md` (для глаз) и `signatures/metrics.json`
  (для скриптов): рамка чернил, базовая линия, вынос, пропорция, масштаб и итоговый размер в pt.
  Пересчитывается `python3 scripts/sig_metrics.py` после любого изменения набора образцов.

## Механика вставки

Вставка делается **инкрементальным обновлением PDF**: исходные байты файла не перезаписываются,
всё дописывается в конец новой ревизией, старая версия документа остаётся внутри файла. В файле
таким образом остаются только следы добавления подписи.

В конец файла дописываются:

- объекты изображения подписи (RGB + SMask-альфа, FlateDecode);
- при необходимости объекты шрифта — TrueType Liberation Sans + FontDescriptor + FontFile2,
  `WinAnsiEncoding` + `/Differences [230 /cacute]` для сербского `ć`;
- контент-стрим с отрисовкой;
- обновлённые объекты страницы, контента и ресурсов;
- обновлённый `/Info` с новым `/ModDate`;
- новая xref-секция с `/Prev` на старую.

`/ModDate` ставится в текущее время: подписание — реальное изменение документа. `/CreationDate`
**не трогаем** — это когда документ создали клиент или банк.

Поддерживается только классическая xref-таблица с `trailer` (все документы клиента и банка такие).
Xref-поток (PDF 1.5+) — повод остановиться и разобрать файл руками.

## Структура документов

Скрипты **не содержат зашитых номеров объектов**: страница, `/Contents` и `/Resources` находятся
разбором (`scripts/pdfobj.py`). Реально встречались две раскладки акта:

| | акты 1–17 (Samsung) | акты 18–22 (macOS Quartz) |
|---|---|---|
| Страница 2 | объект 24 | объект 14 |
| Контент | массив в объекте 31 | массив в объекте 32 |
| Ресурсы | объект 26, **уже содержит `/XObject`** | объект 16 |

Отсюда два требования, которые легко нарушить при правках:

- **`/XObject` в ресурсах надо сливать, а не перезаписывать** — иначе с бланка или акта исчезают
  уже имеющиеся картинки.
- **Если `/Contents` указывает на объект, который сам является массивом**, ссылку на новый
  контент-стрим надо дописывать **внутрь этого массива**. Попытка задать странице
  `/Contents [32 0 R X 0 R]` даёт `Syntax Error: Weird page contents`, и страница пустеет.

Поддержанные формы `/Contents`: ссылка на поток, массив в объекте, инлайн-массив.
Формы `/Resources`: ссылка на словарь, инлайн-словарь. Всё остальное — падение с сообщением.

## Остаточная матрица преобразования

Контент-стримы страницы склеиваются в один поток, поэтому незакрытый `cm` на нулевой глубине
`q`/`Q` из исходного потока действует и на дописанный нами контент. Бланк из «Microsoft: Print
To PDF» начинается с `0.75 0 0 -0.75 0 841.5 cm` **вне** `q/Q` — без инверсии текст уезжает
и мельчает. `pdfobj.residual_ctm` считает остаток, `inv` инвертирует, скрипт подставляет
инверсию в начало своего стрима. У многостраничных бланков матрица считается по каждой странице
отдельно.

## Заполнение бланков банка

Никаких фиксированных координат:

- страница с таблицей ищется по слову `STATISTIKU`, страница подписи — по `Mesto` +
  `Pečat i potpis`; это могут быть **разные** страницы, тогда обновляются обе;
- столбцы — по заголовкам `Redni broj`, `Šifra osnova`, `Br.`, `Godina`, `Opis transakcije`,
  `Iznos`; клетка для каждого значения определяется по центру своего заголовка (просто считать
  границы слева нельзя: у бланка есть внешняя рамка, которая сдвигает нумерацию);
- границы клеток и строка данных — по линиям таблицы в растре 150 dpi; рамки двойные, поэтому
  близкие линии склеиваются (зазор ≤6 px);
- линии под `Mesto i datum` и `Pečat i potpis` светло-серые, ищутся мягким порогом.

В `Izjava` текст печатается на самой линии от её начала, но базовая линия текста поднята над
чертой на глубину нижних выносных элементов шрифта — иначе хвосты «g», «/», «@» наезжают на
черту. Цвет заливки задаётся **явно чёрным** (`0 g`): без этого наследуется цвет, оставшийся
от контента бланка, и текст выходит синим.

## Что означают падения проверки

`scripts/verify_signed.sh` ловит именно те способы всё испортить, которые уже случались:

| Симптом | Причина |
|---|---|
| `Syntax Error: Weird page contents`, пустая страница | контент-стрим подключён неверно (см. про массив выше) |
| текст уехал или помельчал | не инвертирована остаточная матрица преобразования |
| с бланка исчезли элементы | `/XObject` перезаписан вместо слияния |
| изменились исходные байты | обновление не инкрементальное |
| `/ModDate` не обновился | не дописан обновлённый `/Info` |

## Состав скриптов

| Файл | Назначение |
|---|---|
| `scripts/pdfobj.py` | разбор PDF: xref, страницы, `/Contents`, `/Resources`, растр, матрицы, запись ревизии |
| `scripts/sign_pdf.py` | акт приёма-передачи; здесь же геометрия подписи (`norm_scale`, `baseline_row`) |
| `scripts/sign_bank.py` | `Obaveštenje o prilivu`: таблица, место и дата, подпись |
| `scripts/sign_izjava.py` | `Izjava / Statement`: имя, контакты, две подписи |
| `scripts/sig_metrics.py` | разметка образцов подписи → `signatures/METRICS.md`, `signatures/metrics.json` |
| `scripts/pdf_probe.py` | диагностика структуры PDF, когда подписыватель упал |
| `scripts/verify_signed.sh` | проверка результата: байты, рендер, текст, даты |
| `scripts/pausal_import.py` | файлы импорта в бухгалтерский сервис из данных месяца |
| `scripts/kpo_book.py` | книги KPO по годам и сводный реестр, курсы НБС |

Зависимости — только `python3` и `poppler-utils` (`pdftotext`, `pdftoppm`, `pdfinfo`).
Обработка изображений своя, без PIL и ImageMagick.
