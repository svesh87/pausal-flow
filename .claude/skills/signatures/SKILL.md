# Библиотека образцов подписи

Все пути — от корня данных. Образцы — самое чувствительное в репозитории: не потому, что
подпись больше нигде не лежит (она стоит в каждом отправленном документе), а потому что это
концентрат — чистые PNG на прозрачном фоне, готовые к вставке. Хранить их зашифрованными
ничего не стоит, поэтому в git идёт **только контейнер**
`signatures/samples.tar.gz.gpg`, а открытые PNG не коммитятся никогда и удаляются сразу
после упаковки.

| Команда | Что делаю |
|---|---|
| «Собери библиотеку подписей» | из сканов сделать набор PNG, посчитать разметку, упаковать |
| «Добавь образцы подписи» | то же для новых сканов, старые образцы сохраняются |
| «Пересобери контейнер образцов» | упаковать заново уже готовую папку с PNG |

Человеческое описание, зачем набор и что сканировать, — `docs/signatures.md`. Здесь порядок
работы.

## Зачем набор, а не одна картинка

Подпись руки каждый раз немного разная. Один и тот же файл, вставленный пиксель в пиксель
в двенадцать документов, выглядит штампом — и по нему видно, что подпись электронная.
Набор из 10–15 образцов даёт в каждый документ свой вариант; скрипты подписи выбирают
образец случайно, а для двух колонок акта берут два разных.

## Что нужно от владельца

1. **Лист с образцами**: 10–15 подписей от руки на белой бумаге, синей шариковой или гелевой
   ручкой, с интервалами (чтобы не сливались), отсканированный **не ниже 600 dpi**.
2. **Сканы уже подписанных документов** — банковские формы, договоры, карточка счёта: там
   подпись стоит в рабочих условиях и выглядит естественнее, чем на чистом листе.
3. Ничего больше. Фотографии с телефона годятся хуже (тени, перспектива), но если это всё,
   что есть, — работать можно.

Сканы владелец приносит в `tmp/inbox/` или называет папку. **Сами сканы в репозиторий
не кладутся**: в них есть и подпись, и данные документа.

## Порядок

Работа идёт в `tmp/signatures-work/` — вне git, удаляется в конце.

1. **Рендер.** PDF — в PNG высокого разрешения:

   ```bash
   pdftoppm -r 900 -png "<скан>.pdf" tmp/signatures-work/page
   ```

   900 dpi — тройное суперсэмплирование относительно 300: дальше идёт уменьшение, и оно
   съедает шум сканера, а не край штриха. Итоговая ширина образца получается 1300–2000 px.
   Готовые картинки (JPG/PNG со сканера) берутся как есть.

2. **Выделение чернил.** Оставить только синие чернила, убрать всё остальное: чёрный текст
   документа, линии, галочки, печати, серый фон бумаги. Признак чернил — синий канал заметно
   выше красного и зелёного (`B - max(R, G) > порог`, порог подбирается по картинке);
   у чёрного текста разница около нуля, у бумаги тоже. Результат — маска чернил.

3. **Чистка.** По маске выбросить:

   - мелкие связные компоненты (пыль, точки от печати) — меньше нескольких сотен пикселей
     в масштабе 900 dpi;
   - образцы, где в кадр попала чужая подпись или элементы документа;
   - **перечёркнутые и явно неудачные подписи** — на листе такие обычно есть.

4. **Кроп и поля.** Обрезать по рамке чернил и добавить поле ~240 px (в масштабе 900 dpi)
   со всех сторон: скриптам подписи нужно место, они позиционируют образец по базовой линии
   письма, а не по краю картинки.

5. **Плотность штриха.** Тонкая часть работы, из-за которой подпись выглядит живой:

   - гладкое плотное ядро штриха: размытие маски плюс `smoothstep` — резкий порог даёт
     рваные края, а чистое размытие — вату;
   - обратно наложить фактуру чернил из оригинала: локальные перепады плотности — это то,
     чем ручка отличается от заливки;
   - бледные окончания штрихов не обрезать порогом, а поднять гаммой: иначе у подписи
     отваливаются хвосты;
   - цвет чернил — **оригинальный попиксельно**, без унификации; шум цвета убирать
     усреднением по чернильным пикселям окна 5×5, не подмешивая фон.

6. **Сохранение.** RGBA PNG с прозрачным фоном, имена `sig_NN_<откуда>.png`
   (`sig_01_card_p2.png`, `sig_07_sheet.png`) — по номеру видно порядок, по суффиксу
   источник. **Конкретные документы в именах не называть**: имя файла попадёт в разметку,
   а разметка — в репозиторий.

   **PNG обязан быть без фильтров строк** (filter 0): скрипты подписи разбирают PNG сами,
   без внешних библиотек, и фильтры не поддерживают. Pillow пишет так по умолчанию;
   ImageMagick — с `-define png:compression-filter=0`. Признак ошибки — падение следующего
   шага с «PNG with filters not supported».

   Библиотеки для шагов 2–5 (Pillow, numpy) движку не нужны и в его зависимостях
   не числятся: они требуются один раз, при сборке набора. Если их нет — поставить
   в отдельное окружение (`python3 -m venv tmp/sigenv && tmp/sigenv/bin/pip install pillow
   numpy`) и не тащить в `requirements-dev.txt`.

7. **Разметка.** Геометрия каждого образца — рамка чернил, базовая линия, вынос, масштаб:

   ```bash
   python3 scripts/sig_metrics.py tmp/signatures-work
   ```

   Кладёт рядом `metrics.json` (для скриптов) и `METRICS.md` (для глаз). Пересчитывается
   после **любого** изменения набора — по этим числам подпись встаёт одинакового размера
   и в акте, и в бланке банка.

8. **Упаковка.** Контейнер шифруется на GPG-ключ из `profile.json` (`gpg.recipient`):

   ```bash
   python3 scripts/signatures.py --pack tmp/signatures-work
   ```

   Пишет `signatures/samples.tar.gz.gpg` в корне данных. Туда же скопировать `metrics.json`
   и `METRICS.md` — они нужны скриптам и не содержат самих подписей.

9. **Уборка и проверка.**

   ```bash
   rm -rf tmp/signatures-work tmp/sigenv
   python3 scripts/signatures.py --list        # что оказалось внутри контейнера
   git status --short signatures/              # в индексе только *.gpg и разметка
   ```

   Открытых PNG на диске не остаётся: скрипты подписи расшифровывают контейнер в память
   при каждом запуске.

10. **Проверить на документе.** Собрать демо-акт и подписать его:

    ```bash
    python3 scripts/make_examples.py tmp/example-data
    python3 scripts/sign_pdf.py tmp/example-data/months/2026_06/acceptance_1.pdf \
                                tmp/example-data/acceptance_1_signed.pdf
    scripts/verify_signed.sh tmp/example-data/months/2026_06/acceptance_1.pdf \
                             tmp/example-data/acceptance_1_signed.pdf --look
    ```

    Посмотреть глазами: подпись по центру поля, базовая линия чуть ниже линии документа,
    хвосты пересекают линию. Если размер выглядит не тем — дело в разметке, а не в образце:
    масштаб нормируется по площади чернил к эталону в `sig_metrics.py`.

## «Добавь образцы подписи»

То же самое, но набор не пересобирается с нуля: сначала распаковать существующий контейнер
в рабочую папку (`python3 scripts/signatures.py --list` покажет состав; расшифровка —
через `signatures.load()`), добавить новые PNG с продолжением нумерации, пересчитать
разметку и упаковать заново. Старые образцы не переделывать: они уже стоят в отправленных
документах.

## Границы

- **Сканы и открытые PNG в git не попадают** — ни в движок, ни в данные. В данных
  `signatures/*.png` закрыт `.gitignore`, а пре-коммит проверяет индекс.
- **Подписанное и отправленное не переподписывается** после смены набора: в документах
  у контрагентов стоят прежние образцы, и это нормально.
- `gpg` может ждать касания токена или ввода PIN — команда, которая выглядит подвисшей,
  скорее всего ждёт оператора. Не считать это зависанием.
- Если владелец приносит один-единственный образец — сказать, что набор из одного файла
  превращает подпись в штамп, и попросить лист. Работать при этом можно.
