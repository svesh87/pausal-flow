# Настройка с нуля

От свежего клона движка до состояния «можно закрывать месяц». Всё локально: ничего никуда
не отправляется, ни одного аккаунта не создаётся.

Быстрый путь — сказать агенту «Настрой окружение»: навык `setup` проведёт по этим же шагам
и будет спрашивать по одному блоку. Ниже то же самое для чтения глазами.

## 0. Из чего всё состоит

Два репозитория:

- **движок** (этот) — публичный: навыки, скрипты, документация, шаблоны. Ни одного реквизита,
  ни одного документа;
- **данные** — приватный, только у владельца: `profile.json`, `months/`, `finance/`,
  `contracts/`, `signatures/`.

Связывает их симлинк `engine` внутри данных. Скрипты движка сами находят корень данных:
переменная `TASKS_DATA`, либо ближайший вверх от текущего каталога каталог с `profile.json`.
Поэтому работа идёт **из каталога данных**, а скрипты вызываются по пути движка.

## 1. Клон движка и системные пакеты

```bash
git clone https://github.com/svesh87/pausal-flow.git && cd pausal-flow
```

Дальше — пакеты:

| Нужно | Зачем | Пакет в Debian/Ubuntu |
|---|---|---|
| `pdftotext`, `pdftoppm`, `pdfinfo` | разбор PDF, рендер, проверка подписанного | `poppler-utils` |
| `soffice` | сборка книг КПО из HTML в PDF | `libreoffice-calc` |
| `gpg` | шифрование контейнера образцов подписи | `gnupg` |
| `git` | история правок данных и движка | `git` |
| `python3` ≥ 3.10 | всё остальное — стандартной библиотекой | `python3` |

Проверить одним разом:

```bash
python3 scripts/doctor.py
```

Он перечислит, чего не хватает, и назовёт пакет. Дальше — окружение разработки; оно нужно
только тому, кто будет править движок:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
```

Если `venv` падает на отсутствии `ensurepip` (в Debian и Ubuntu это отдельный пакет
`python3-venv`), выручает `virtualenv .venv`: он приносит `pip` с собой и системных пакетов
не требует.

## 2. Приватный репозиторий данных

```bash
scripts/init_private.sh ~/docs/ip-data
```

Что появится в каталоге данных:

```
profile.json          скопирован из profile.example.json — заполнять его
engine -> …           симлинк на движок (в .gitignore)
.claude/skills -> …   симлинк на навыки движка (в .gitignore)
CLAUDE.md             тонкий: импортирует engine/CLAUDE.md плюс местные заметки
.gitignore            engine, tmp/, открытые PNG подписей, кэш
.githooks/pre-commit  не пустить открытые образцы подписи в коммит
months/ finance/ contracts/ signatures/ docs/ tmp/inbox/
```

Скрипт идемпотентен: повторный запуск ничего не переписывает. Если каталог уже репозиторий
git, `git init` он не делает и печатает команду для включения хука.

Дальше все команды — из каталога данных:

```bash
cd ~/docs/ip-data
python3 engine/scripts/doctor.py
```

## 3. `profile.json`

Единственное место, где живут реквизиты. Образец с заглушками — `profile.example.json`,
структура та же.

| Блок | Что внутри | Откуда взять |
|---|---|---|
| `entrepreneur` | имя, фирма, ПИБ, шифра делатности, адрес, место издавања, телефон, ящик | решение о регистрации, решение налоговой; `izjava_name` — как имя написано в банковских бланках |
| `accounts` | динарский счёт, девизный счёт, его IBAN, цифры личного счёта | карточка счёта из банка; IBAN — тот, что клиент указывает в платеже |
| `mail` | ящик, папка писем банка, папка выписок, отправитель счетов поставщиков | почтовый клиент; путь к папке брать из результата поиска, а не собирать руками — в IMAP кириллица приходит в modified UTF-7 |
| `integrations` | чем закрыты роли `tasks`, `chat`, `mail`, `accounting` | `docs/integrations.md` |
| `client` | название, адрес, налоговый номер, канал и учётка в мессенджере, языки сообщения и акта | договор с клиентом; языки — на каких он читает список работ и на каких выписан акт |
| `suppliers` | по каждому: имя, прежнее имя, жиро-счёт, предмет | счета поставщиков |
| `gpg` | получатель, на которого шифруется контейнер образцов | `gpg --list-keys` |
| `limits` | годовой лимит паушала | актуальный порог в законе |

Пустое поле лучше выдуманного: скрипт падает с понятным сообщением на пустом и молча делает
неверный документ на выдуманном. Незаполненные заглушки доктор показывает отдельной строкой.

## 4. Интеграции

Роли и способы подключения — `docs/integrations.md`. Коротко: нужны источник задач, канал
с клиентом, почта. Всё, что через них приходит, — читается; всё, что уходит, — только
черновиком, отправляет человек.

## 5. Образцы подписи

Без них работает всё, кроме подписания. Как собрать набор с нуля — `docs/signatures.md`,
либо сказать агенту «Собери библиотеку подписей» (навык `signatures`).

## 6. Проверка на синтетике

Убедиться, что цепочка живая, до появления первых настоящих документов:

```bash
python3 engine/scripts/make_examples.py tmp/example-data
TASKS_DATA=tmp/example-data python3 engine/scripts/tax_registry.py
TASKS_DATA=tmp/example-data python3 engine/scripts/build_report.py
TASKS_DATA=tmp/example-data python3 engine/scripts/kpo_book.py --offline
```

Появятся `tmp/example-data/finance/report.md` и `finance/kpo/kpo_2026.pdf` из выдуманных
чисел. Чего на синтетике нет: разбора выписок банка (нужны настоящие PDF своего банка,
вёрстка у каждого своя) и выгрузки в бухгалтерский сервис (сверяется по трём документам).

## 7. Хуки и гейты

В движке:

```bash
scripts/install_hooks.sh     # pre-commit: проверка, что в движке нет ничего личного
.venv/bin/ruff check scripts/
.venv/bin/pytest -q
scripts/check_clean.sh
```

В данных хук включает `init_private.sh` (или команда, которую он печатает). Имена
собственные, которые не должны попадать в движок, перечисляются в `.check_clean.local`
в корне данных — по строке на слово; файл приватный и в git не идёт.

Гейты движка запускаются из каталога движка, а там `profile.json` не найти — проверка
по значениям и стоп-листу молча выключится. Чтобы этого не было, положить в корень движка
файл `.tasks_data` с путём к каталогу данных (относительный считается от корня движка):

```bash
echo ../ip-data > .tasks_data      # файл в .gitignore, у каждого свой
```

## 8. Первый месяц

```
«Собери задачи»                  → months/ГГГГ_ММ/tasks.md на ревью
«Отправь список в чат»           → черновик клиенту
«Подпиши документы из чата»      → акт и инвойс, подпись, проверка
«Отправь документы в чат»        → черновик с подписанным актом
«Подпиши документы банка»        → бланк уведомления о приливе
«Отправь документы в банк»       → окно ответа с четырьмя вложениями
«Выгрузи в pausal.rs»            → файлы импорта в бухгалтерский сервис
«Обнови книги КПО»               → finance/kpo/
```

Плюс раз в месяц «Обнови финансы» — банк, счета поставщиков, налоги, пересборка.

## Если что-то не так

- `python3 scripts/doctor.py` — что именно не готово и чем починить;
- скрипт упал с сообщением про форму документа — форма изменилась, разбираться по
  `.claude/skills/sign-docs/internals.md`, раздел «Если документ изменился»;
- сервер MCP не поднялся — `docs/integrations.md`, раздел «Проверка и диагностика»;
- «нет файла реквизитов» — корень данных не найден: запускать из каталога данных
  или задать `TASKS_DATA`.
