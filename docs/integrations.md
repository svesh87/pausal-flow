# Интеграции: какие роли нужны движку и чем их закрыть

Скрипты работают с файлами. Всё, что приходит извне — письма банка, документы клиента,
задачи из трекера, — приходит через MCP-серверы. Движок не привязан к конкретным продуктам:
он опирается на **роли**, а какой инструмент закрывает роль у этого владельца, написано
в `profile.json`, секция `integrations`.

## Роли

| Роль | Что от неё нужно | Кто использует |
|---|---|---|
| `tasks` — источник задач | найти закрытые за период задачи исполнителя; прочитать заголовок, описание, комментарии, связи | навык `monthly-tasks` |
| `chat` — канал с клиентом | найти файлы в переписке, скачать вложение, прочитать тред, положить **черновик** сообщения | навыки `monthly-tasks`, `sign-docs` |
| `mail` — почта | найти письмо в папке по отправителю и датам, скачать вложение, открыть **окно ответа** | навыки `finance`, `sign-docs` |
| `accounting` — бухгалтерский сервис | принять два XLSX импорта (артикул, счёт) | навык `sign-docs` |

Секция в конфиге выглядит так (значения — пример):

```json
"integrations": {
  "tasks": {"kind": "youtrack", "mcp": "youtrack", "projects": ["PROJ"], "assignee": "login"},
  "chat":  {"kind": "slack", "mcp": "slack"},
  "mail":  {"kind": "thunderbird", "mcp": "thunderbird-mail"},
  "accounting": {"kind": "pausal.rs"}
}
```

Если нужного сервера в сессии нет — навык говорит об этом и останавливается, а не ищет
обходные пути.

## Как заменить инструмент

Роль — это несколько глаголов, а не продукт. Чтобы поставить на её место другой инструмент:

1. поправить `kind` и `mcp` в `profile.json`;
2. переписать раздел «Адаптер» в навыках, где эта роль используется: там перечислены
   конкретные вызовы. Тело навыка говорит про роль и правки не требует;
3. проверить, что правило «наружу уходит только черновик» выполняется и новым инструментом.
   Если у него нет черновиков — не отправлять вовсе, а печатать текст и путь к файлу, чтобы
   владелец отправил сам.

Что менять при этом **не** нужно: парсер выписок, категоризацию, реестры, сводный отчёт,
книги КПО, подпись PDF и проверку подписанного — ядро от продуктов не зависит.

Ролям `tasks` и `chat` подходит любой трекер и любой мессенджер с MCP: Jira, Linear, GitLab
Issues; Telegram, Mattermost, почта вместо мессенджера. Роль `accounting` — любой сервис
с импортом из XLSX; шаблоны импорта лежат в `scripts/templates/pausal/` и меняются вместе
с сервисом.

## Способ подключения 1: локальный мост без секретов (почта)

Роль `mail` у автора закрыта Thunderbird MCP — расширением Thunderbird плюс Node-мостом
к нему. Секретов не требует вообще: доступ к ящикам задаётся в настройках самого расширения
(Tools → Add-ons → Thunderbird MCP → Options), а не через MCP.

**Откуда взять:** <https://github.com/TKasperczyk/thunderbird-mcp>. Установка: клонировать
репозиторий, поставить в Thunderbird XPI расширения из `extension/` (или готовый из `dist/`),
а `mcp-bridge.cjs` из корня клона прописать в конфиг как команду. Обновление — `git pull`
в клоне плюс переустановка XPI, если она поменялась: мост и расширение должны быть одной
версии.

Блок в `~/.claude.json`:

```json
"thunderbird-mail": {
  "type": "stdio",
  "command": "<путь>/node",
  "args": ["<путь>/thunderbird-mcp/mcp-bridge.cjs"],
  "env": {}
}
```

Особенности, о которые легко споткнуться:

- Thunderbird должен быть **запущен**: мост общается с живым приложением, а не с почтовым
  сервером напрямую;
- `getMessage(saveAttachments=true)` сохраняет вложения во временную папку и возвращает путь —
  содержимое PDF в контекст не тянется, поэтому объём документов работе не мешает;
- Thunderbird в путях к сохранённым вложениям заменяет пробелы на `_` и добавляет `-1`, если
  файл уже скачан: итоговое имя надо брать из `attachments[].name`, а не строить самому;
- в папках IMAP с кириллицей `folderPath` приходит в modified UTF-7 — брать его из результата
  `searchMessages`, а не собирать вручную.

## Способ подключения 2: сервер с токеном (трекер)

Роль `tasks` у автора закрыта YouTrack. В актуальных версиях YouTrack MCP-эндпоинт уже
встроен в сам сервер: отдельный локальный сервер поднимать не нужно, достаточно указать
адрес инсталляции и токен по инструкции своей версии. Отдельный MCP-сервер (свой или
сторонний) нужен только там, где встроенного нет — например, на старой версии.

**Токен в конфиг не кладётся.** Проверенная схема: в конфиге стоит только имя записи
в парольном хранилище, а обёртка достаёт её и передаёт настоящей команде. Обёртка
(`~/.local/bin/passenv`) экспортирует строки `KEY=value` из записи `pass` и делает `exec`:

```bash
#!/usr/bin/env bash
set -euo pipefail
umask 077

if (($# < 2)); then
    echo "Usage: passenv <namespace> <command> [args...]" >&2
    exit 64
fi

namespace="$1"
shift

if [[ ! "$namespace" =~ ^[a-z0-9][a-z0-9_-]*$ ]]; then
    echo "Invalid namespace: $namespace" >&2
    exit 64
fi

lock_dir="${XDG_RUNTIME_DIR:-$HOME/.cache}"
mkdir -p "$lock_dir"

exec 9>"$lock_dir/passenv-mcp.lock"
flock 9

# Command substitution propagates a failed `pass show`.
payload="$(pass show "mcp/$namespace")"

while IFS= read -r line || [[ -n "$line" ]]; do
    line="${line%$'\r'}"

    [[ -z "$line" || "$line" == \#* ]] && continue

    if [[ ! "$line" =~ ^[A-Za-z_][A-Za-z0-9_]*= ]]; then
        echo "Invalid entry in mcp/$namespace" >&2
        exit 65
    fi

    export "$line"
done <<< "$payload"

unset payload line

flock -u 9
exec 9>&-

exec "$@"
```

Запись создаётся `pass insert -m mcp/<namespace>`, внутри строки вида:

```
YOUTRACK_URL=https://youtrack.example.com
YOUTRACK_API_TOKEN=perm:...
```

Зачем здесь `flock`: `pass` дёргает GPG-агент, а серверы поднимаются параллельно при старте
сессии. Без блокировки несколько `pass show` одновременно спорят за агент, и часть запросов
падает или подвисает на запросе PIN. Блокировка снимается перед `exec`, поэтому на время
работы сервера ничего не заперто.

Схема годится для любого сервера, которому нужен токен, — не только для трекера.

## Способ подключения 3: коннектор, а не файл (канал)

Роль `chat` у автора закрыта Slack, а он подключается в настройках claude.ai (раздел
коннекторов) — в `~/.claude.json` его нет. Поэтому в headless-запусках и в cron его может
не быть: это нормально, шаги с каналом просто не выполняются.

Два ограничения, которые нужно помнить всегда:

- **`slack_send_message_draft`, а не `slack_send_message`** — прямая отправка добавляет
  к сообщению «Sent using Claude», и это уходит клиенту;
- **загрузки файлов у Slack MCP нет вообще**: ни черновик, ни сообщение не принимают вложений.
  Подписанный акт владелец прикладывает к черновику руками, поэтому навык обязан назвать
  полный путь к файлу.

## Почта — только окно ответа

`replyToMessage` **без** `skipReview` открывает окно составления, `sendMail` не используется.
Кнопку «Отправить» жмёт человек. Отправителя (`from`) задавать явно, иначе почтовый клиент
может подставить не ту личность.

## Проверка и диагностика

- `/mcp` в сессии — список серверов и их состояние;
- сервер в состоянии «still connecting» — не ошибка: контейнеры поднимаются несколько
  секунд, инструменты появятся;
- сервер не поднялся — запустить его команду руками в терминале: обёртка `passenv` печатает
  понятные ошибки (`Invalid entry in mcp/<namespace>`, отсутствие записи в `pass`);
- `pass show mcp/<namespace>` — проверить, что запись на месте и в ней ожидаемые ключи;
- `python3 scripts/doctor.py` — какие роли закрыты по конфигу и чего не хватает в окружении.
